# SaaS Boost User and Developer Documentation

## Glossary

**ComputeNest Service**: An orchestrated collection of cloud resources, software, or applications. Once a service is published and goes live, end users can create instances based on these services to access the specific service content provided by the service provider.

**ComputeNest Service ID**: Uniquely identifies a ComputeNest service.

**Service Provider**: A software provider who wishes to commercialize their software.

**User**: The target audience who wants to use the service provider's software.

**ComputeNest SaaS Boost**: An open-source framework developed by ComputeNest. ComputeNest provides a one-click deployment solution for this framework to help service providers quickly commercialize their software.

**ComputeNest SaaS Boost Instance**: A template application created via the ComputeNest one-click deployment solution. Service providers can directly access the Web interface to build their software marketplace and share it with users to sell software. ComputeNest SaaS Boost instances are also deployed via ComputeNest.

**SaaS Boost Product**: A product manually generated by the service provider through the Web interface. It has a unique product code used to associate the software (ComputeNest service) to be sold.

**SaaS Boost Public Access Address**: The public IP or domain name bound to this SaaS Boost instance, used for public network access by both service providers and users, as well as for API interaction with ComputeNest.

**SaaS Boost Plan**: Each product can be configured with different plans, such as Basic, Standard, and Premium, each with a different price.

**ComputeNest Service Plan**: The plan on the ComputeNest service side, which allows parameter management for different plans.

## Introduction

ComputeNest SaaS Boost is an open-source payment and subscription management framework launched by Alibaba Cloud. It aims to help software developers quickly build, deploy, scale, and sell software based on ComputeNest (**supporting both private deployment and fully managed mode**), opening up the path to software commercialization. It provides a set of out-of-the-box features and components that allow users to focus on business logic development while greatly reducing the complexity and cost of deploying software to the cloud. ComputeNest SaaS Boost offers many features, including:

1. **Selling Capability**: Achieve rapid software sales through bidirectional binding of ComputeNest services and SaaS Boost products. Supports domestic Alipay payment.
2. **ComputeNest Capability**: SaaS Boost is built on Alibaba Cloud ComputeNest, accelerating the deployment, delivery, and management of software services in the cloud, enabling cloud onboarding within a week.
3. **Multi-Tenant Architecture**: SaaS Boost provides powerful multi-tenant data isolation and management capabilities for multi-tenant applications, making it easy for developers to build and manage data for multiple tenants.
4. **CI/CD Capability**: ComputeNest SaaS Boost provides Cloud Flow pipelines that support CI/CD, enabling developers to automate code build, test, and deployment. This accelerates iteration and delivery of new features, improving development efficiency and product quality.
5. **Plan Management**: SaaS Boost provides multi-plan configuration, allowing developers to flexibly define and manage different plans while handling billing and quotas.
6. **SaaS Application Monitoring**: SaaS Boost provides monitoring capabilities to help developers track and analyze application performance and health, and promptly identify and resolve issues.

#### Difference Between ECS and ACK Deployment Modes

In ECS mode, the main service is deployed on an ECS machine, and scheduled tasks are published to Alibaba Cloud FC via function compute. This mode includes a built-in Cloud Flow pipeline, allowing service providers to implement CI/CD directly after modifying code.
In ACK mode, deployment is done via Helm to the corresponding ACK cluster. There is no built-in pipeline; users need to build the server image (containing Boost.server and boost.front code) and the Job image (Boost.serverless) themselves and manage them independently.

### Deployment Process

The process for deploying ComputeNest SaaS Boost is as follows:

#### 1. **Create a ComputeNest Service**

1. **Configure your SaaS application (ComputeNest Service)**:
    - Create your ComputeNest Service. See the Developer Guide - Quick Service Creation section below. For more details, see the official documentation [Quick Service Creation](#quick-service-creation).

#### 2. **Fork the Current Repository**

Fork the current repository to your personal repository.

#### 3. **Create an Alipay Sandbox Account**

The parameters highlighted in the guide images will be used when creating a service instance. The steps for creating an Alipay sandbox account and creating a ComputeNest service instance can be reversed.

1. Follow the instructions in the [Alipay Sandbox Documentation](https://open.alipay.com/develop/sandbox/app) to create an Alipay sandbox account. The application gateway address and authorization callback address should be filled in after the service instance is created.

2. Retain the private key of the Alipay sandbox application and the official Alipay public key.

#### 4. **Create a ComputeNest Service Instance**

1. Access the [ComputeNest Console](https://computenest.console.aliyun.com/) and select [SaaS Boost One-Click Deployment Service](https://computenest.console.aliyun.com/service/instance/create/cn-hangzhou?type=user&ServiceId=service-fd1aec438c974828bb7b).
2. Fill in the deployment parameters as prompted:

   1. Select the service to deploy.
   2. Select the deployment region.
   3. Enter Alipay sandbox information (optional).
   4. In the pipeline configuration, create your enterprise. Create Git connection credentials based on the forked repository information and enter the forked repository address.

      1. Create a Cloud Flow enterprise.
      2. Enter the pipeline.
      3. Click **Global Settings** and enter it.
      4. Select GitHub Service Connection in the upper right corner and create a new one.
      5. Authorize on GitHub.

   5. Select payment type, ECS instance type, and deployment availability zone.
   6. Select/create a VPC and switch (VSW). To reduce the number of parameters to fill in, it is recommended to select "Create New".

3. Confirm and agree to the service agreement, then click **Create Now** to enter the deployment phase. Wait for resource creation and pipeline execution to complete.

4. Fill in parameters after the service instance is created (optional):
    1. Fill in `AlipayNotifyUrl` and `AlipayReturnUrl` from the deployed instance information back into the application gateway address and authorization callback address in the Alipay sandbox application configuration (Step 3.1).
    2. Wait for the pipeline to complete. You can check the pipeline execution progress as shown in the documentation.
    3. Pipeline runs successfully.

#### 5. **Access the ComputeNest SaaS Boost Service**

Click the Endpoint on the deployed service instance details page to access the SaaS Boost interface.

### Usage

Once ComputeNest SaaS Boost is deployed (for ECS deployment, also wait for the pipeline to complete), you can start using it to develop, deploy, and sell your software applications. Here are some key usage instructions:

1. Configure/modify service plans (optional):
    - Upload [deployment artifacts](https://help.aliyun.com/zh/compute-nest/deployment-object-management/?spm=a2c4g.11174283.0.i2) or use [quick ROS templates](https://help.aliyun.com/zh/ros/use-cases/?spm=a2c4g.11174283.0.0.5c3848aezYq1dI) to build your ComputeNest Service.
    - Configure plans in the `application.properties` file.
    - Re-run the pipeline to complete SaaS application deployment.

2. **Alipay Sandbox Testing (Required)**: Before official selling, use the Alipay sandbox APP to test selling capabilities.
    1. If you skipped configuring Alipay information when creating the ComputeNest service instance, you need to configure it before use. See the section "Modifying Alipay Service Configuration".
    2. Download the Alipay client sandbox Android APP from the Alipay sandbox tools.
    3. Select the software product you want to purchase on the featured services page.
    4. Use the account and password provided in the sandbox app to test payment.
    5. View the deployed service instance details.
    6. View deployed service instance monitoring.
    7. View order history.

3. After passing sandbox testing, be sure to test again using an official Alipay account:
    1. Access the [Alipay Developer Console](https://open.alipay.com/develop/manage).
    2. Create a web/mobile application.
    3. Fill in the application name, merchant account, and icon as prompted.
    4. Configure the following parameters in order:
       1. Select interface encryption. Choose key encryption method.
       2. Download the official key generation tool. Click "Generate Key".
       3. Upload the obtained public key.
       4. Download the Alipay public key.
       5. Set the interface encryption method to AES.
       6. Set the application gateway address (Alipay's callback address after payment), corresponding to `AlipayNotifyUrl` in service instance details.
       7. Set the authorization callback address (the page Alipay redirects to after payment), corresponding to `AlipayReturnUrl` in service instance details.
       8. Change the sandbox Alipay gateway address in the activated `application-*.properties` in the boost.common package to the official gateway address. Replace the sandbox official Alipay public key in the config file with the official public key.
       9. Modify your application private key and Alipay application public key in the OOS parameter repository. See Developer Guide - Modifying OAuth Service Configuration.
       10. Re-run the pipeline.
    5. Conduct an official Alipay purchase test.

## Developer Guide

### SaaS Boost Product and Plan Management Guide

This document guides how to properly manage and price products on the SaaS Boost platform, and how to maintain consistency between products and ComputeNest services and plans.

#### Product and Service Association

Each product created on the SaaS Boost platform should correspond to a single service in ComputeNest. Merchants can set a base price for the product based on this service.

#### Creating a Product

1. Log in to SaaS Boost.
2. Navigate to the **Product Management** page.
3. Click the **Add Product** button to enter the creation interface.
4. Enter service-related information and fill in the corresponding ComputeNest Service ID in the `Service ID` field.
5. Complete the product information, including name, description, and base pricing.
6. Click Submit to complete product creation.

#### ComputeNest-Side Plans

Plans here are used to manage the software and hardware parameters of deployments.
Through the plan configuration feature, service providers can configure some or all parameters of a service as plans for users to choose from, avoiding high learning costs or configuration errors when users configure many parameters in a single service.

Service providers can configure multiple plans to provide users with the best configuration practices for different scenarios.

When creating a service instance, a plan must be selected, and then the parameters outside the plan can be configured to create a service instance.
For more details, see the ComputeNest official documentation: [Configure Plans](https://help.aliyun.com/zh/compute-nest/create-package-settings-for-a-service).

#### SaaS Boost-Side Plans

Plans here are used to manage the pricing of ComputeNest plans.
Each plan set for a product in SaaS Boost should correspond to the corresponding service plan in ComputeNest. The name of each plan must be exactly the same as the plan name in ComputeNest. In this process, developers should first configure [plans in ComputeNest](https://help.aliyun.com/zh/compute-nest/create-package-settings-for-a-service?spm=a2c4g.11174283.0.i5), and then customize the price for those plans in SaaS Boost.

#### Unified Plan Naming

To ensure a consistent user experience, make sure the plan names in ComputeNest match the plan names on SaaS Boost.

#### Adding SaaS Boost Plans and Pricing

1. Select a created product and enter its plan management interface.
2. Click **Add Plan** to enter the plan detailed configuration page.
3. Accurately enter the corresponding plan name from ComputeNest in the `Plan Name` field.
4. Set a price based on the plan configuration.
5. Save the new plan after confirming the information is correct.

#### Key Points to Note

- Keep the plan names on SaaS Boost strictly consistent with the plan names in ComputeNest.
- Consider the specific configuration of the corresponding ComputeNest service plan when pricing.
- Regularly review and update the plan correspondence between SaaS Boost and ComputeNest to maintain data currency and accuracy.

By following these guidelines, merchants can ensure proper integration and price consistency between products on the SaaS Boost platform and the services and plans in ComputeNest.

### Modifying Configuration Parameters in Parameter Management

To better sell your products, you need to configure personal information management and payment information management in advance. Personal information includes the service provider name, official link, Logo link, and service provider profile. This information helps you better showcase your details to users. Payment information management will support multiple payment methods in the future, but currently only supports Alipay for receiving payments. The parameters you need to configure in Alipay include the Application ID, Merchant ID, official public key, service provider private key, and payment environment. This section will explain in detail what content needs to be filled in for each parameter in personal information and payment information, and the rules to follow.

#### Modifying Service Provider Personal Information

The Logo link in personal information supports both local paths and HTTP URLs. Other information can be filled in according to your needs.

#### Configuring Alipay

##### Preparation Phase

Before configuring Alipay parameters, you need to ensure your application has been connected to the Alipay Open Platform. If you need to register your application, visit the [Alipay Developer Console](https://open.alipay.com/develop/manage).
If you encounter difficulties during registration, refer to the Alipay Open Platform [Technical Integration Guide](https://opendocs.alipay.com/common/02mse2?pathHash=a0991bdc).

##### Configuration Items Introduction

The Alipay configuration items include Application ID, Merchant ID, official public key, service provider private key, and payment environment. Among these, Application ID, Merchant ID, and payment environment are regular parameters, while the official public key and service provider private key are encrypted parameters. SaaS Boost uses Alibaba Cloud OOS to ensure the security of your private information.

**Application ID** is a unique identifier assigned by Alipay to each application or website that integrates its payment service. It is used to identify the specific merchant application and ensure that requests come from authorized merchants. When initiating a payment request, this ID must be included so that the Alipay platform can identify and route to the correct merchant account.

**Merchant ID** is a unique number assigned by Alipay to merchants, used to identify the merchant's identity. It works together with the Application ID to determine the payee of a transaction. The Merchant ID is essential when processing payment, refund, and other business logic, ensuring that funds flow to the correct merchant account.

**Official Public Key** refers to the public key provided by Alipay, used to verify the authenticity of messages or notifications sent by Alipay to merchants. In encrypted communication, merchants use Alipay's public key to decrypt data sent by Alipay or verify Alipay signatures, confirming that messages have not been tampered with and ensuring transaction security.

**Service Provider Private Key** is the private key agreed upon between Alipay and the merchant, part of the RSA asymmetric encryption system, paired with the public key provided by Alipay. Before initiating a payment request, merchants sign transaction information with their private key. Alipay verifies the signature using the public key upon receiving the request, ensuring the request comes from a trusted source. This process is crucial for preventing data tampering and ensuring transaction integrity.

**Payment Environment** includes sandbox and production environments. The sandbox environment is a simulated real payment environment for developers to test payment functionality without real financial transactions. In the sandbox environment, you can safely debug code and test payment processes. Once the application's payment functionality has been tested without issues in the sandbox environment, you can deploy it to the production environment. The production environment is directly associated with actual financial transactions; payment operations performed here involve real monetary flows.

##### How to Obtain the Configuration Values

1. The Application ID can be viewed in the upper left corner of the Console tab on the Alipay Open Platform after your application is successfully registered.

2. The Merchant ID can be viewed at Alipay Open Platform -> Avatar in the upper right corner -> Account Center -> Account Management -> Account Information -> Account ID.

3. For obtaining the official public key and service provider private key, refer to the Alipay Open Platform documentation [View Key/Certificate](https://opendocs.alipay.com/common/057aqe?pathHash=9e740611).

4. Set the payment environment according to your own situation. Safely debug code and test payment processes in the sandbox environment before switching to the production environment.

## Common Errors and Solutions

1. **Pipeline Run Error**
    The pipeline includes npm build and Java build. After the build, the FC jar package is uploaded to the OSS repository, and the server jar package is uploaded to the ComputeNest artifact repository. After uploading, actual deployment is performed: FC deployment is done by directly replacing the zip package in OSS, and server deployment is done by executing the `deploy.sh` script in the current project. After familiarizing yourself with the overall pipeline steps, you can identify common development issues by combining the error logs provided by the pipeline.
    If it is difficult to resolve in the cloud, you can clone the error environment locally.

2. **Service Instance Deployment Failure**
    This situation is commonly caused by insufficient permissions for the user creating the service instance, or the selected ECS instance type being sold out in the current availability zone.
    More detailed information can be viewed in the deployment logs on the service instance details page.
